# Инструкция по демонстрации фронтенда

## Порядок показа

### 1. Показать три страницы фронтенда с mock данными (без запущенного сервиса)

#### Шаг 1.1: Запуск фронтенда без бэкенда

```bash
cd gase-frontend
npm install
npm run dev
```

Приложение будет доступно по адресу `http://localhost:3000`

#### Шаг 1.2: Демонстрация страниц

1. **Главная страница** (`http://localhost:3000/`)
   - Показать слайд-шоу из 3 изображений
   - Показать надпись "GasProject" по центру
   - Объяснить, что слайды меняются автоматически каждые 3 секунды

2. **Страница каталога газов** (`http://localhost:3000/gases`)
   - Показать список газов из mock данных
   - Показать поиск по названию
   - Показать корзину (иконка 📋) с количеством 0
   - Показать карточки газов с дефолтными изображениями
   - Показать кнопку "Добавить в расчеты"

3. **Страница детального просмотра** (`http://localhost:3000/gases/1`)
   - Показать детальную информацию о газе
   - Показать breadcrumbs навигацию
   - Показать изображение (или дефолтное)

#### Шаг 1.3: Проверка mock данных

- Открыть DevTools (F12)
- Перейти на вкладку Console
- Показать сообщения об использовании mock данных при ошибках запросов
- Показать файл `src/modules/mock.ts` с mock данными

### 2. Показать страницы фронтенда с бэкендом

#### Шаг 2.1: Запуск бэкенда

```bash
# В корневой директории проекта
go run cmd/GaseProject/main.go
```

Бэкенд должен быть запущен на `http://localhost:8080`

#### Шаг 2.2: Проверка работы с бэкендом

1. **Открыть DevTools → Network**
   - Показать запросы к API
   - Показать, что запросы идут через прокси на `/api/gases`
   - Показать, что прокси перенаправляет на `http://localhost:8080/api/gases`

2. **Показать проксирование в vite.config.ts**
   ```typescript
   proxy: {
     "/api": {
       target: "http://localhost:8080",
       changeOrigin: true,
       rewrite: (path) => path.replace(/^\/api/, "/api"),
     },
   }
   ```

3. **Проверить работу фильтров**
   - Ввести поисковый запрос в поле поиска
   - Показать в Network, что запрос уходит с параметром `?search=...`
   - Показать ответ от бэкенда

#### Шаг 2.3: Показать изображения из MinIO

1. **Проверить изображения в карточках**
   - Если у газа есть `image_url`, показать его
   - Показать в Network запросы к изображениям
   - Показать URL изображений из MinIO (например, `http://localhost:9000/bucket/image.jpg`)

2. **Показать дефолтное изображение**
   - Если у газа нет изображения, показать дефолтное (`/DefaultImage.svg`)
   - Объяснить, что дефолтное изображение используется при отсутствии `image_url`

#### Шаг 2.4: Показать работу корзины

1. **Добавить газ в корзину**
   - Нажать кнопку "➕ Добавить в расчеты" на любой карточке
   - Показать в Network запрос `POST /api/gases/:id/add-to-draft`
   - Показать, что счетчик корзины обновился

2. **Проверить счетчик корзины**
   - Показать запрос `GET /api/cart` в Network
   - Показать ответ с количеством газов в корзине
   - Показать обновленную иконку корзины с числом

### 3. Внести изменения в БД и показать их во фронтенде

#### Шаг 3.1: Добавить новый газ в БД

**Вариант 1: Через API (если есть эндпоинт)**

```bash
curl -X POST http://localhost:8080/api/gases \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Аргон",
    "formula": "Ar",
    "molar_mass": 39.948,
    "description": "Инертный газ, используемый в лампах накаливания"
  }'
```

**Вариант 2: Через SQL**

```sql
INSERT INTO gas (title, formula, molar_mass, description) 
VALUES ('Аргон', 'Ar', 39.948, 'Инертный газ, используемый в лампах накаливания');
```

#### Шаг 3.2: Показать изменения во фронтенде

1. **Обновить страницу каталога**
   - Нажать F5 или кнопку обновления
   - Показать, что новый газ появился в списке
   - Показать в Network запрос `GET /api/gases` с новыми данными

2. **Проверить детальную страницу**
   - Перейти на страницу нового газа
   - Показать, что данные загружаются из БД
   - Показать в Network запрос `GET /api/gases/:id`

#### Шаг 3.3: Обновить существующий газ

**Через SQL:**

```sql
UPDATE gas 
SET description = 'Обновленное описание газа' 
WHERE id = 1;
```

**Показать изменения:**
- Обновить страницу детального просмотра
- Показать, что описание обновилось
- Показать в Network актуальные данные

#### Шаг 3.4: Добавить изображение к газу

1. **Загрузить изображение через MinIO (если есть эндпоинт)**

```bash
curl -X POST http://localhost:8080/api/gases/1/image \
  -F "file=@path/to/image.jpg"
```

2. **Или обновить image_url в БД**

```sql
UPDATE gas 
SET image_url = 'http://localhost:9000/bucket/gas-image.jpg' 
WHERE id = 1;
```

3. **Показать изображение во фронтенде**
   - Обновить страницу
   - Показать, что изображение загрузилось
   - Показать в Network запрос к изображению из MinIO

## Дополнительные моменты для демонстрации

### Показать структуру проекта

```
gase-frontend/
├── src/
│   ├── components/      # Компоненты (Navbar, Breadcrumbs, GasCard)
│   ├── pages/          # Страницы (HomePage, GasesPage, GasDetailPage)
│   ├── modules/        # API модули (gasApi.ts, cartApi.ts, mock.ts)
│   └── Routes.tsx      # Конфигурация маршрутов
├── public/             # Статические файлы (изображения для слайд-шоу)
└── vite.config.ts      # Конфигурация Vite с прокси
```

### Показать ключевые файлы

1. **vite.config.ts** - проксирование для CORS
2. **src/modules/gasApi.ts** - работа с API и fallback на mock
3. **src/modules/cartApi.ts** - работа с корзиной
4. **src/pages/GasesPage.tsx** - страница с фильтрами и корзиной
5. **src/pages/HomePage.tsx** - слайд-шоу

### Показать особенности реализации

1. **Mock данные при ошибках** - показать в `gasApi.ts`, как при ошибке используются mock данные
2. **Проксирование** - показать, как Vite проксирует запросы для решения CORS
3. **Дефолтные изображения** - показать использование дефолтного изображения
4. **Breadcrumbs** - показать навигационную цепочку на всех страницах
5. **Корзина** - показать обновление счетчика после добавления газа
